# PRD — iambox

> 기준일: 2026-09-30. **구현**은 현재 코드, **예정**은 기존 PRD의 제품 요구사항, **TBD**는 미확정 사항을 뜻한다. 코드와 다르면 실제 코드를 확인하고 문서를 갱신한다.

## 프로젝트 개요

- 프로젝트명: 앱 이름 `iambox`, 저장소 `iambox_app`.
- 목적: 학습용 MVP에서 시작하여 실제 셀프스토리지 서비스로 확장한다.
- 서비스 설명: 주변 지점을 찾고 보관 공간을 선택한 뒤 결제하고 QR로 출입하는 모바일 서비스 **예정**.
- 대상 사용자: 보관 공간을 찾고 이용하려는 개인 사용자로 해석한다. 세부 고객군은 **TBD**.
- 대상 플랫폼: iOS / Android. Expo 설정의 태블릿 지원·웹 favicon만으로 별도 태블릿 UX나 웹 서비스 제공을 확정하지 않는다.

## 현재 구현 상태

- pnpm 워크스페이스에 `mobile/`, `api/`가 있다.
- 앱은 홈 · 지점찾기 · 출입QR · 이삿짐 · 마이 하단 탭을 표시한다. 홈에는 소개, 물품 보관 카드와 오른쪽 택배요청·케어서비스 카드, 원형 바로가기 4개(창업문의·지점 찾기·출장서비스·공지사항), 이벤트 배너·후기 예시를 표시한다. 홈의 지점 찾기는 기존 탭으로 이동하며 나머지 서비스는 준비 안내를 연다.
- 출입QR 탭에는 이용 중인 보관 공간, 기간, 남은 일수, 방문 안내와 문의 UI를 표시한다. 성수점 A-024의 mock 데이터를 사용하며 버튼은 예시 이용 내역·안내 모달을 연다. 실제 출입 QR 발급·인증, 지도 길찾기, 문의 접수는 미구현이다.
- `출입 QR 열기`로 QR 안내창을 열면 앱이 활성 상태인 동안 화면을 최대 밝기로 설정한다. 닫기·뒤로가기·화면 이탈·앱 전환 시 이전 밝기로 복원하고 QR을 유지한 채 돌아오면 다시 높인다. Android는 기존 시스템 밝기 사용 상태도 복원한다. 밝기 기능은 네이티브 모듈을 포함한 앱에서 동작하며 실기기 확인은 대기 중이다. 다른 안내 모달의 밝기는 변경하지 않는다.
- 지점찾기 탭에는 `@mj-studio/react-native-naver-map` 기반 네이버 기본 지도와 예시 지점 3개의 마커를 표시하는 코드를 추가했다. 타입 검사·iOS/Android 번들·네이티브 설정 검증은 통과했으며 실제 Client ID 발급과 개발용 앱 빌드·기기 검토는 대기 중이다. Expo Go에서는 준비 안내를 표시한다. 행정구역 개수·가격·목록은 후속 단계다.
- 서버는 `GET /`에 `Hello World!` 문자열을 반환한다.
- Prisma의 PostgreSQL 연결과 연결 확인 CLI가 있다. 스키마에 모델은 없다.
- 앱–API 연결과 실제 인증·지점 조회·공간 계약·결제·QR 발급 기능은 미구현이다. 홈과 출입QR의 UI는 정적 예시 데이터로 표시한다.

Node.js 22.23.3은 루트 README에 기록된 구성 환경이며 package.json에 engines로 강제하지 않는다. 지도 라이브러리는 `@mj-studio/react-native-naver-map` `2.9.0`을 사용하고 `expo-dev-client`로 개발용 앱을 실행한다. 라우터, 전역 상태 관리, QR·결제 SDK는 아직 없다.

초기 MVP 제외: 관리자 앱, 추천 AI, 복잡한 멤버십, 쿠폰 시스템, 정기 결제, 고급 통계.
예약을 별도 기능으로 제공할지, 이용 기간·재고를 어떻게 관리할지는 **TBD**다. `Reservation`은 모델 후보이지 확정된 예약 기능이 아니다.

### 지점찾기 상세 요구사항 — 1단계 진행 중 (2026-09-30)

- 사용자 설명 기준 현재 약 300개 지점이며 향후 증가를 고려한다. 실제 지점 데이터는 아직 저장소에 연결되지 않았다.
- 지도를 축소하면 강남구·서초구처럼 행정구역별 정확한 지점 개수를 표시하고, 확대하면 개별 지점의 가격·특가 할인 문구·특징을 표시한다. 거리 기반 자동 군집으로 지역 개수를 대신하지 않는다.
- 지도와 지점 목록을 전환할 수 있으며 선택한 지점을 서로 연결한다.
- 군집별 최저가 집계는 이번 범위에 포함하지 않는다.
- 우선 예시 데이터로 모바일 화면을 구현하고, 실제 지점 API·DB 연동은 후속 범위로 둔다.
- 기본 지도 → 행정구역 개수 → 가격·특가 마커 → 목록 연동 → 안정성·규모 검증 순서로 진행하며, 각 단계 결과를 사용자가 검토한 뒤 다음 단계로 넘어간다.
- iOS·Android 지도 제공자는 네이버로 통일한다. 집계 기준·화면 동작·검증 기준은 [Architecture의 승인 설계와 진행 기록](ARCHITECTURE.md#지점찾기-지도-설계와-단계별-진행)을 따른다. 클러스터 패키지는 도입을 보류했으며 현재 네이버 지도 라이브러리·네이티브 인증 설정과 예시 마커 코드까지 적용했다. 1단계 기기 화면과 사용자 검토 후 다음 단계로 진행한다.

## 핵심 사용자 흐름

현재: 앱 실행 → 홈 블록 화면 → 하단 탭 선택 → 출입QR은 mock 내 공간 화면, 지점찾기는 예시 지도, 나머지 메뉴는 임시 화면 표시. 출입QR 화면의 버튼으로 이용 내역과 안내 모달을 열고 닫을 수 있다. 지점 지도는 기기 실행 검토를 기다린다.

다음은 **예정** 흐름이다. 로그인 필수 시점과 예외 흐름은 TBD다.

```text
앱 실행 → 회원가입/로그인 → 홈 → 지도 또는 지점 목록
→ 지점 선택 → 상세 확인 → 보관 공간 선택 → 기본 결제 → 이용 시작
앱 → QR 화면 → QR 인증 → 출입
홈 → 마이페이지 → 사용자 정보 확인
```

## 개발 원칙

- 작은 MVP부터 시작한다.
- 요청된 단계만 구현하고 다음 단계 기능을 미리 구현하지 않는다.
- 실제 필요가 생겼을 때 구조를 확장한다.
- 기존 패턴을 우선하며 사용하지 않는 레이어와 과도한 추상화를 만들지 않는다.
- 예정 기능을 현재 동작으로 설명하지 않는다. 구현 시 이 문서의 상태도 바꾼다.
