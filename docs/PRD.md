# PRD — iambox

> 기준일: 2026-10-01. **구현**은 현재 코드, **예정**은 기존 PRD의 제품 요구사항, **TBD**는 미확정 사항을 뜻한다. 코드와 다르면 실제 코드를 확인하고 문서를 갱신한다.

## 프로젝트 개요

- 프로젝트명: 앱 이름 `iambox`, 저장소 `iambox_app`.
- 목적: 학습용 MVP에서 시작하여 실제 셀프스토리지 서비스로 확장한다.
- 서비스 설명: 주변 지점을 찾고 보관 공간을 선택한 뒤 결제하고 QR로 출입하는 모바일 서비스 **예정**.
- 대상 사용자: 보관 공간을 찾고 이용하려는 개인 사용자로 해석한다. 세부 고객군은 **TBD**.
- 대상 제품 플랫폼: iOS / Android. Expo 설정의 태블릿 지원·웹 favicon만으로 별도 태블릿 UX나 웹 서비스 제공을 확정하지 않는다. Next.js 웹은 같은 모노레포의 공통 코드 확인용 기본 화면까지 구성했으며 실제 웹 제품 흐름은 후속 범위다.

## 현재 구현 상태

- 택배 탭은 제공받은 SVG 그림, 서비스 소개와 접수·수거/배송·실시간 조회 특징 3개를 표시한다. `택배 이용하기`와 `이용 방법이 궁금하신가요?`는 각각 별도의 빈 중앙 팝업을 열며 닫기 기능만 제공한다. 설정 아이콘, 접수 폼, 실제 수거·배송 조회, 이용 방법 본문은 미구현이다.

- pnpm 워크스페이스에 `mobile/`, `api/`가 있다.
- 마이페이지는 예시 프로필, 나의 박스·이용 내역·결제 내역·문의하기 바로가기, 이용 관리(알림설정·택배예약·사전예약·케어서비스), 고객지원(공지사항·FAQ·문의하기), 로그아웃 버튼과 약관·개인정보처리방침 링크를 표시한다. 나의 박스는 기존 출입QR의 내 공간 화면으로 이동하고 이용 내역은 기존 mock 안내, 나머지 메뉴는 예시·준비 안내 모달을 연다. 약관과 개인정보처리방침은 모달 표시만 구현했으며 정식 본문·인증·로그아웃·알림 설정 변경·예약 접수·결제 조회는 미구현이다. 이용후기와 이용 중인 공간 요약 카드는 표시하지 않는다.
- 앱은 홈 · 지점찾기 · 출입QR · 택배 · 마이 하단 탭을 표시한다. 홈에는 소개, 물품 보관 카드와 오른쪽 택배요청·사전방문 카드, 원형 바로가기 4개(창업문의·지점 찾기·AI 견적·공지사항), 이벤트 배너·후기 예시를 표시한다. 홈의 지점 찾기는 기존 탭으로 이동하며 나머지 서비스는 준비 안내를 연다.
- 출입QR 탭에는 이용 중인 보관 공간, 기간, 남은 일수, 방문 안내와 문의 UI를 표시한다. 성수점 A-024의 mock 데이터를 사용하며 버튼은 예시 이용 내역·안내 모달을 연다. 실제 출입 QR 발급·인증, 지도 길찾기, 문의 접수는 미구현이다.
- `출입 QR 열기`로 QR 안내창을 열면 앱이 활성 상태인 동안 화면을 최대 밝기로 설정한다. 닫기·뒤로가기·화면 이탈·앱 전환 시 이전 밝기로 복원하고 QR을 유지한 채 돌아오면 다시 높인다. Android는 기존 시스템 밝기 사용 상태도 복원한다. 밝기 기능은 네이티브 모듈을 포함한 앱에서 동작하며 실기기 확인은 대기 중이다. 다른 안내 모달의 밝기는 변경하지 않는다.
- 지점찾기 탭은 네이버 지도에 강남점·서초점·성수점의 mock 좌표와 가격을 표시한다. 사용자 제공 로고의 왼쪽 심볼·지점명·시작 가격을 담은 3px 보라색 말풍선 마커를 누르면 선택 지점을 갱신하고 예시 상세 화면으로 바로 이동한다. 화면 이름에는 mock 접두사를 넣지 않고 `mockLocations`와 ID에서 구분하며, 상세 화면에는 예시 데이터 안내를 표시한다. 지도·상세는 React Navigation Native Stack으로 이동하며 iOS 왼쪽 가장자리 스와이프 뒤로가기를 지원한다. 상세에서 지도 복귀 시 검색·필터·시트 상태와 카메라를 유지한다. 지도 하단에는 접힘·중간·펼침 높이를 가진 공통 바텀 시트와 스크롤 가능한 예시 지점 목록을 표시한다. 목록은 이미지·이름·위치 아이콘이 있는 주소·최저가를 표시하며, 선택한 행과 지도 마커를 같은 ID로 강조한다. 지점 행 전체를 누르면 마커와 같이 바로 상세 화면으로 이동한다. 목록은 주소 → 이용 가능한 사이즈 → 최저가 순서다. 화면 최상단 지도 바로 위에 고정 배치한 지역·지점명 검색과 사이즈 필터를 지도·목록에 함께 적용한다. 검색 영역은 바텀 시트 밖에 있어 시트를 펼쳐도 상단에 유지된다. 사이즈 필터는 모달에서 임시 선택한 뒤 적용하고 활성 칩으로 삭제한다. 목록 상단의 지점 수 제목·펼치기/접기 버튼·예시 데이터 안내는 표시하지 않는다. 손잡이 터치와 드래그로 높이를 바꾸며 상세 복귀 시 시트 높이도 유지한다. 접힌 상태와 드래그 중에도 시트 안의 목록 일부를 유지한다. 초기 10개 행과 이후 최대 10개 배치로 가상화하고 스크롤에 따라 추가 행을 렌더링한다. 실제 API 페이지 조회는 후속 범위다. Expo Go는 준비 안내를 표시한다. 좌표 클러스터와 목록 선택 카메라 이동은 구현했다. 특가·지도/목록 모드 전환·실제 지점 API는 후속 단계다.
- Next.js `web/`은 기본 실행 구조를 구성했다. 공통 UI 확인용 예시 내용은 사용자 요청으로 제거해 현재 홈 화면은 비어 있다. 공유 패키지 설정은 유지하며 API·로그인·결제·지도는 연결하지 않았다. [통합 검증 기록](superpowers/plans/2026-10-02-monorepo-stage6.md)을 따른다.
- 서버는 `GET /`에 `Hello World!` 문자열을 반환한다.
- Prisma의 PostgreSQL 연결과 연결 확인 CLI가 있다. 스키마에 모델은 없다.
- 앱–API 연결과 실제 인증·지점 조회·공간 계약·결제·QR 발급 기능은 미구현이다. 홈과 출입QR의 UI는 정적 예시 데이터로 표시한다.

### 지점찾기 상세 요구사항 — 클러스터·가격·상세 이동 (2026-10-02)

- 사용자 설명 기준 현재 300개 이상 지점이며 향후 증가를 고려한다. 실제 지점 데이터는 아직 저장소에 연결되지 않았다.
- 지도를 축소하면 가까운 좌표의 클러스터 개수를 표시하고, 확대하면 실제 분리 결과로 개별 지점의 가격을 표시한다. 공통 지역명은 보조 라벨이며 특가·특징은 후속 범위다.
- 지도와 지점 목록을 전환할 수 있으며 선택한 지점을 서로 연결한다.
- 군집별 최저가 집계는 이번 범위에 포함하지 않는다.
- 우선 예시 데이터로 모바일 화면을 구현하고, 실제 지점 API·DB 연동은 후속 범위로 둔다.
- 2026-10-02 승인 계획에 따라 기존 행정구역 강제 집계·격자/48개 제한을 Naver Map + Supercluster로 대체했다. 가까운 지점을 좌표 기준으로 묶고 bbox·정수 zoom의 실제 결과로 개수 Cluster와 가격 Point를 함께 표시한다. 공통 district만 라벨로 붙이며 숫자는 구 전체 총계가 아니다.
- Cluster 클릭은 분리되는 확대 수준으로 450ms 이동한다. 카메라 이동 중 마커를 유지하고 idle에서 새 마커를 150ms 페이드로 반영한다. 최대 확대에서 분리되지 않는 같은 좌표 지점은 기존 시트 목록으로 선택한다.
- 지도·목록 선택은 selectedBranchId 갱신 → 기존 상세 화면으로 즉시 이동 순서다. 중간 요약 시트는 표시하지 않고 시트 높이도 바꾸지 않는다. 최대 확대의 클러스터 구성 목록에서 진입하면 상세 복귀 시 그 목록을 유지한다. 필터에서 선택 지점이 제외되면 전체 결과 목록으로 돌아간다. 상세 복귀 시 검색·필터·선택·시트·카메라를 유지한다.
- 말풍선은 이름/가격 실측에 따라 폭 120~280pt·이름 두 줄, PNG/SDK 캐시는 각각 128개다. 생성은 하나씩 수행하고 실패·포화에는 기본 핀·캡션을 제공한다. 기본 예시는 3개이며 개발 플래그로 350개 분산/밀집 검증 데이터를 제공한다. 1,000개는 자동 검증용 증가 가정이다. 실제 API 및 실기기 성능 보장을 뜻하지 않는다.
- 자세한 데이터 경계·검증 제한은 [Architecture](ARCHITECTURE.md#지점찾기-지도-설계와-단계별-진행)를 따른다.

## 핵심 사용자 흐름

현재: 앱 실행 → 홈 블록 화면 → 하단 탭 선택 → 출입QR은 mock 내 공간 화면, 지점찾기는 mock 가격 지도와 지점 상세, 마이는 예시 프로필·메뉴 화면, 택배는 서비스 소개 화면 표시. 택배의 이용하기·이용 방법 버튼은 각각 빈 중앙 팝업을 연다. 마이의 나의 박스는 출입QR 탭으로 이동한다. 출입QR·마이의 버튼으로 이용 내역과 안내 모달을 열고 닫을 수 있다. 지점 마커·목록을 선택하면 바로 예시 상세로 이동한다. 뒤로가기로 지도로 복귀한다.

다음은 **예정** 흐름이다. 로그인 필수 시점과 예외 흐름은 TBD다.

```text
앱 실행 → 회원가입/로그인 → 홈 → 지도 또는 지점 목록
→ 지점 선택 → 상세 확인 → 보관 공간 선택 → 기본 결제 → 이용 시작
앱 → QR 화면 → QR 인증 → 출입
홈 → 마이페이지 → 사용자 정보 확인
```

| 결제 | 기본 결제 진행·결과 확인 | 예정 |
| 출입QR / 내 공간 | 이용 중인 보관함·기간 확인, 방문 안내·문의 | mock UI와 안내 모달 구현, 실제 QR 발급·출입 인증 예정 |
| 마이페이지 | 예시 프로필, 내 공간 이동, 이용 관리·고객지원, 약관 링크 | UI·탭 이동·안내 모달 구현, 실제 서비스·계정·정식 약관 연결 예정 |
| 택배 | 서비스 소개·특징 3개·이용하기·이용 방법 | UI·빈 중앙 팝업 연결 구현, 접수·조회·안내 본문 예정 |

하단 탭은 홈 · 지점찾기 · 출입QR · 택배 · 마이 순서다. 지점찾기의 지도·목록과 지점 상세에서도 하단 탭을 계속 표시하며 다른 탭으로 이동할 수 있다. 지도·목록 화면 최상단에는 검색창과 필터만 표시한다. 지점 상세의 상단 뒤로가기는 지도·목록으로 돌아간다. Android 뒤로가기는 지점 상세 닫기 → 필터 모달 닫기 → 펼친 목록 접기 → 진입 전 화면 복귀 순서로 처리한다. 탭 선택은 App.tsx의 로컬 상태로 관리하며, 지점 지도·상세는 `LocationsStack`의 Native Stack 경로로 이동한다. iOS 상세의 가장자리 스와이프와 `<` 버튼은 지도 경로로 복귀한다. 택배 접수·조회와 팝업 내부 내용은 후속 범위다.

## 개발 원칙

- 작은 MVP부터 시작한다.
- 요청된 단계만 구현하고 다음 단계 기능을 미리 구현하지 않는다.
- 실제 필요가 생겼을 때 구조를 확장한다.
- 기존 패턴을 우선하며 사용하지 않는 레이어와 과도한 추상화를 만들지 않는다.
- 예정 기능을 현재 동작으로 설명하지 않는다. 구현 시 이 문서의 상태도 바꾼다.
